# 연습 문제 (활성 Spec 아님)

공개 사례는 내일 출제 문제의 예측 근거가 아니라 **연습할 문제 유형의 참고**다. 출제 확률이나 확정 여부를 뜻하지 않는다.
공통 기반이 맞는 문제군: 문서·데이터를 입력받아 → 코드가 검증·판정하고 → Claude가 근거를 연결해 설명·초안을 쓰고 → 사람이 검토·내보내기.

| 우선순위 | 가상 문제 | 참고한 공개 사례·유형 | 준비 수준 | 바꿀 부분 |
|---|---|---|---|---|
| 1 | CSV 오류 검증 + 결과보고서 초안 | Code with Kiro 갤러리의 데이터 활용 프로젝트(NetCraft AI 등) | **작동 예제** (`src/domain/program-report.ts`) | 입력 스키마, 집계, 보고서 문구 |
| 2 | 규정·매뉴얼 기반 절차 안내 | SchoolGuard 개발 후기의 교육 자료·검토 흐름 | **어댑터 예제** (`src/domain/examples/regulation-guide.ts`) | 규정 데이터, 조건 판단, 근거 표시 |
| 3 | 고객 문의·민원 분류와 응답 초안 | 생산성 도구, GitGovernance의 결정 추적에서 착안 | 설명만 (아래) | 분류 기준, 담당자 규칙, 답변 형태 |
| 4 | 학습 자료를 설명·활동으로 변환 | Why Should I Care 등 교육 프로젝트 | 설명만 (아래) | 학습 목표, 설명 수준, 활동 카드 |

## 문제 3 — 민원 분류와 응답 초안 (설명만)

- 사용자: 학과 사무실 민원 담당자 1명
- 입력: 문의 CSV(접수일, 채널, 제목, 본문) — 가상 데이터
- 코드 판정: 필수값·중복 접수 검사, 키워드·규칙표로 담당 부서와 처리 기한(접수 + N일) 계산
- Claude: 규칙 결과(부서·기한·규칙 ID)를 근거로 답변 초안. 분류가 불확실하면 cautions로 "확인 필요"
- 바꿀 파일: 새 어댑터 + 규칙표 fixture. 공통 엔진(근거 ID 검증·검토·내보내기) 그대로

## 문제 4 — 학습 자료 → 설명·활동 카드 (설명만)

- 사용자: 비교과 프로그램 강사 1명
- 입력: 학습 목표 목록 + 자료 텍스트(붙여넣기) — 가상 자료
- 코드 판정: 목표별 키워드가 자료에 있는지(근거 문단 번호), 분량·난이도 지표
- Claude: 목표별 쉬운 설명과 활동 카드 초안, 각 카드에 근거 문단 ID 연결
- 바꿀 파일: 텍스트 입력 어댑터(CSV 대신 문단 분리), AI 출력 구조가 카드형이면 `schema.ts`·`DraftPanel`·`markdown.ts` 함께 수정
