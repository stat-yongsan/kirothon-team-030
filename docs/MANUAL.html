문제를 받으면 이 네 가지만 하면 된다

  1. challenge.md의 문제 원문 칸에 받은 문제를 그대로 붙여 넣고 저장한다. 복사본 같은 다른 파일이 아니다(1단계).
  2. PowerShell에서 기준점을 저장하고 kiro-cli를 builder 에이전트로 연다. 이 단계는 기본(auto) 모델로 한다.

kiro-cli --agent builder                     # 검사 Hook이 붙은 에이전트
  3. 채팅에 아래 문장을 붙여 넣는다. 만들 결과물을 1~6으로 못 박은 문장이다.

1문제가 공개되면: challenge.md 채우기 5분

  1. notepad D:\kiro\challenge.md로 연다. 파일 이름을 확인한다 — 연습 때 다른 파일에 붙여 넣어 적용이 안 됐다.
  2. ## 문제 원문 아래 대괄호 줄을 지우고 받은 문제를 요약·수정 없이 그대로 붙여 넣는다.
  3. 아는 것만 채운다: 발표 시간, 심사 기준/제출 형식, 제공 자료, Figma 프레임 URL. 모르는 칸은 그대로 둔다 — 에이전트가 가정으로 표시한다.
    • 이메일·계정 정보는 넣지 않는다. 이 파일은 제출 저장소에 올라간다.
    • 한 칸을 고친 뒤 다음 줄이 붙어 버리지 않았는지 본다. 항목마다 한 줄씩이어야 한다.
    • ## 이번 MVP 같은 제목 줄의 ##를 지우지 않는다. 에이전트가 이 제목으로 칸을 찾는다.
  4. Figma 프레임 링크(디자인을 쓸 때만)
    • Figma 왼쪽 레이어 패널에서 카드 같은 프레임 하나만 클릭 → 우클릭 → 복사/붙여넣기 옵션 → 선택 항목 링크 복사.
    • 링크의 node-id=가 0-1이면 페이지 전체라서 다시 복사한다. 연습 때는 카드가 아니라 사진 8장 묶음(MENU ITEMS)을 가리켜서 디자인이 반영되지 않았다.
    • 프레임 안 레이어 이름을 영어로(title, price, badge…) 붙여 두면 더 정확히 읽는다.
  5. "이번 MVP" 칸(제목·사용자·입력…)은 지금 고치지 않아도 된다. 다음 단계에서 에이전트가 원문에 맞게 바꾼다.
  6. 제공 데이터 파일이 있으면 프로젝트 안(예: docs/provided/)에 두고 "제공 자료" 칸에 경로를 적는다. 실제 개인정보가 있으면 넣지 말고 "가상 데이터로 만들어"라고 요청한다.
  7. 저장한다(Ctrl+S).

2주제 변경 요청 20~30분

  1. 기준점을 저장하고 builder로 연다(builder에만 검사 Hook이 붙어 있다). 모델은 기본(auto) 그대로 둔다. 
    cd D:\kiro
git add -A; git commit -m "주제 변경 전"

    • 처음 열면 "Trust this workspace?"를 묻는다 → 허용해야 에이전트·Hook·MCP가 로드된다.
    • 파일 쓰기·명령 실행 승인 질문은 허용한다. "이 세션 동안 허용" 선택지가 있으면 그것을 고른다.
    • 승인 질문이 계속 나와 느리면 종료 후 kiro-cli --agent builder --trust-all-tools로 다시 연다(이 폴더에서만 쓸 것).
  2. 맨 위의 주제 변경 요청문(결과물 1~6 지정)을 붙여 넣는다.
    • 짧은 요청("SKILL 절차로 갱신해")은 연습 때 절차를 건너뛰었다. 결과물을 번호로 적은 문장은 haiku에서도 1~6을 모두 만들었다.
    • 진행 중 [quality:save], [quality:task] 줄이 보이면 builder Hook이 자동 검사를 돌리는 중이다.
    • 이 단계에서는 Figma·dev 서버·브라우저를 쓰지 않는다. 크레딧을 아끼고, 화면은 3단계에서 내가 직접 본다.

Get-Content src/domain/current.ts -Tail 1

Kiro Crew로 할 때 (선택)

① 왼쪽 세션 목록에서 프로젝트 폴더(예: D:\kiro)의 "새 채팅"으로 연다 → ② 입력창 아래 프로젝트: D:\kiro인지 확인한다(workspace로 되어 있으면 엉뚱한 곳을 고친다) → ③ 에이전트 builder, 승인 모드 신뢰(이 채팅만) → ④ 위 문장 전송.

Kiro Crew에서는 builder의 Hook이 돌지 않는다. 끝나면 "node scripts/quality.mjs task 돌리고 결과 보여줘"를 따로 요청한다. 오른쪽 위 숫자(예: 23/50)가 크레딧 사용량이다.

구현 범위:

5) 어댑터 테스트에 그 값 테스트 1개 추가
dev 서버와 브라우저 확인은 하지 마. AI_MODE=mock 유지, 서브에이전트 금지. 마지막에 node scripts/quality.mjs task PASS를 확인하고 Figma 호출 횟수, data-name, 바뀐 파일을 보고해.

  • Figma 도구 승인 질문이 나오면 허용한다.
  • 보고의 data-name이 내가 고른 프레임 이름인지 본다. 다른 이름이면 링크가 잘못된 것이다(1단계 Figma 링크). 링크를 다시 복사하고 아래 문장으로 1회만 다시 읽힌다.
    kiro-cli 채팅에 붙여넣기 — Figma 다시 읽기

    challenge.md의 새 Figma 프레임 URL로 get_design_context를 1회만 호출해서, 앞서 만든 카드 컴포넌트의 색·글꼴 크기·모서리·간격·배지 모양만 Figma 값대로 바꿔. 다른 파일은 고치지 마. Figma 이미지 asset URL은 쓰지 마. 받은 data-name과 task 검사 결과를 보고해.

  • Figma가 안 되거나(한도·로그인) 링크가 없으면 첫 두 문장을 "Figma 없이 기본 Tailwind 디자인으로 대표 성공 장면의 화면 요소(예: 카드)를 만들어."로 바꿔 보낸다. 디자인보다 장면이 화면에 있는 것이 먼저다.
  • 끝나면 브라우저를 새로고침하고 정상 샘플·오류 샘플을 다시 눌러 본다. 카드 안의 값이 맞는지는 3단계의 좁은 수정으로 고친다.

4-2. 남은 작업 하나씩

tasks.md의 미완료 작업은 이 요청문으로 맡긴다. 7번(실제 Claude)과 8번(배포)은 5단계에서 한다.

kiro-cli 채팅에 붙여넣기

challenge.md와 활성 Spec을 읽고 현재 미완료 작업 하나를 구현해. 해당 인수 조건과 타입·테스트를 실제 검사하고, 실패한 부분만 최대 3회 수정해. 통과하면 멈추고 명령과 결과를 남겨. 반복 상한이면 원인과 최소 다음 조치를 보고해. 새 기능을 추가하지 말고, 실패를 샘플 응답으로 숨기지 마.

  • builder 에이전트에서는 검사를 Hook이 자동으로 돌린다. 파일을 쓰면 lint 검사(save), 응답이 끝날 때마다 타입+테스트 검사(task). 기본 에이전트·Kiro Crew에서는 Hook이 없으니 명령을 직접 요청한다.
  • 내가 직접 코드를 고쳤다면 아래 명령을 실행한다. Hook은 에이전트의 쓰기에만 반응한다. 
    node scripts/quality.mjs task
  • 반복을 통째로 맡기려면 /goal --max 3 <위 요청문>(기본 5회, 취소는 /goal clear).
  • 기능은 3개를 넘기지 않는다. 떠오른 아이디어는 발표의 "다음 단계"로 보낸다.
